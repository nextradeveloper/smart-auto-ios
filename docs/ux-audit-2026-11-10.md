# UX/UI audit — 10 November 2026

## สถานะหลังแก้ไข

แก้ implementation ตามข้อพบแล้ว: ล็อกกลับแบบ best effort แม้ acknowledgement ของ unlock หาย, กันคำสั่งอื่นตลอดช่วงส่งเสียง, แถบ recovery ใน finder และ dashboard, สวิตช์บันทึกทริปมีผลระหว่างขี่, ยืนยันลบทริปทั้งสองทาง, แยก error/empty/retry ในการค้นหาและเส้นทาง, แจ้งผลบันทึกจุดจอด, แก้ทางตันในหน้าตรวจการเชื่อมต่อพร้อมยกเลิกการทดสอบ และประสานการล้างแคชกับ auto-connect

เพิ่ม empty state สำหรับบัญชีไม่มีรถ, ทางกลับ Login เมื่อคำขอที่มี token ได้ HTTP 401/403, คำแนะนำลืมรหัสผ่าน และ reminder ของ consent จากคีย์บอร์ด รวมถึงปรับ route preview ตามพื้นที่ เพิ่มชื่อปุ่มสำหรับ VoiceOver และ layout ปุ่มรถสำหรับตัวอักษร accessibility

เพิ่ม regression tests สำหรับ signal/relock, recording gate, cache maintenance, session recovery, no-vehicle retry และ layout constraints ตรวจ syntax และ diff ได้บน Windows แต่ยังไม่ได้รัน XCTest, build iOS หรือกดตรวจภาพจริง รายการทดสอบบนเครื่องด้านล่างจึงยังคงสถานะยังไม่ได้รัน รูปแบบ authentication failure ที่ตอบ HTTP 200 พร้อม JSON ของ ZONTES ยังต้องยืนยันจากบริการจริงก่อนเพิ่มการตรวจแบบเฉพาะเจาะจง

ข้อพบและวิธีตรวจด้านล่างเป็นบันทึกก่อนการแก้ไข

## วิธีตรวจและขอบเขต

ให้ 3 agent ตรวจแยกกัน: Login/นโยบาย, รถ/นำทาง/ทริป และบัญชี/การเชื่อมต่อ/จัดการข้อมูล จากนั้นตรวจหลักฐานซ้ำจากโค้ดใน workspace ปัจจุบัน

ผลนี้เป็น **code walkthrough** ตามลำดับการใช้งาน ไม่ใช่ usability test กับผู้ใช้จริงหรือผลกดบน iPhone ไม่มี Xcode, xcrun หรือ Swift toolchain ในเครื่อง Windows นี้ ระบบควบคุม native รายงานว่าเชื่อมต่อ native pipe ไม่สำเร็จ และ browser inventory ไม่มีหน้าทดสอบ iOS ที่เชื่อมต่ออยู่ จึงยังไม่ได้วัดภาพหน้าจอ เวลาโหลด การตอบสนองของคีย์บอร์ด หรือ VoiceOver และไม่ได้รัน XCTest ในรอบนี้

รอบนี้เพิ่มรายงานเท่านั้น ไม่ได้แก้พฤติกรรมแอป

## ข้อพบที่ควรแก้ก่อน

### P1 — ให้รถส่งเสียงแล้วล็อกกลับล้มเหลว ไม่มีปุ่มแก้ในหน้าเดียวกัน

- เดิน flow: ค้นหารถ → ให้รถส่งเสียงและกระพริบไฟ → ปลดล็อกสำเร็จ → ล็อกกลับล้มเหลวทั้ง 3 ครั้ง
- กลไก: `SmartAuto/VehicleBluetoothMonitor.swift:227` ส่ง unlock แล้ว lock; เมื่อ lock ล้มเหลวจะรายงานว่ารถยังปลดล็อกอยู่ที่บรรทัด 245
- ผลต่อผู้ใช้: ข้อผิดพลาดแสดงเป็น caption ใต้ปุ่มที่ `SmartAuto/FindVehicleView.swift:247` แต่ไม่มีปุ่ม Lock บนหน้านี้ ผู้ใช้ต้องปิดหน้าค้นหารถแล้วกลับไปหน้ารถ
- แก้: แสดงสถานะที่เด่นและคงอยู่ พร้อมปุ่ม “ล็อกรถอีกครั้ง” ในหน้าค้นหารถ และอธิบายผลของคำสั่งก่อนเริ่ม
- ยังต้องทดสอบ: การรับรู้ข้อความและการกดล็อกซ้ำเมื่อสัญญาณขาด ด้วยระบบจำลองคำสั่งก่อนลองกับรถจริง

### P1 — ปิดสวิตช์บันทึกทริประหว่างขี่ แต่ยังเก็บพิกัดต่อ

- เดิน flow: เปิดจอรถ → เริ่มบันทึกทริป → ไปหน้าทริป → ปิดสวิตช์บันทึก
- กลไก: `SmartAuto/Ride/TripsView.swift:25` เปลี่ยน AppStorage เท่านั้น; `SmartAuto/Ride/TripLog.swift:340` ตรวจ preference ตอน begin ขณะที่ add ที่บรรทัด 353 ตรวจเพียง active
- ผลต่อผู้ใช้: สวิตช์แสดงปิดแต่ยังบันทึก; หากเริ่มเปิดจอรถโดยปิดสวิตช์ไว้ การเปิดสวิตช์ระหว่างทางก็ไม่เริ่มบันทึก
- แก้: ผูกการเปลี่ยนสวิตช์เข้ากับการเริ่ม/หยุด recorder และอธิบายว่าจะเก็บทริปช่วงก่อนปิดอย่างไร

### P2 — Session ใช้ไม่ได้ แต่ไม่มีทางเข้าสู่ระบบใหม่จากข้อความผิดพลาด

- เดิน flow: เปิดแอปด้วย token ที่ใช้ไม่ได้ → ดึงข้อมูลรถล้มเหลว → ปิด alert → รีเฟรชแล้วล้มเหลวซ้ำ
- กลไก: `SmartAuto/ZontesAppModel.swift:84` แสดง error แต่ยังคง session; `SmartAuto/ContentView.swift:12` เลือกหน้าจาก session และ `SmartAuto/ZontesAPI.swift:184` รวม HTTP authentication failure เป็นข้อความระบบไม่พร้อมใช้งาน
- ผลต่อผู้ใช้: ต้องค้นพบเองว่าควรไป บัญชี → ออกจากระบบ
- แก้: แยก authentication failure จาก network error แล้วมี action เข้าสู่ระบบใหม่ โดยไม่ออกจากระบบเมื่ออินเทอร์เน็ตขาดธรรมดา
- ยังต้องยืนยัน: รูปแบบตอบกลับจริงของ ZONTES เมื่อ token หมดอายุ

### P2 — ไม่มีรถพร้อมใช้งาน แต่หน้าจอแนะนำให้ลองโหลดใหม่ซ้ำ

- เดิน flow: login สำเร็จด้วยบัญชีที่ไม่มีรถพร้อมใช้งาน → missingVehicle → หน้ารถแจ้งโหลดไม่สำเร็จ
- หลักฐาน: `SmartAuto/ZontesAPI.swift:71`, `SmartAuto/ZontesAppModel.swift:50`, `SmartAuto/ContentView.swift:143`
- แก้: empty state แยกจาก network failure พร้อมคำแนะนำตรวจการผูกรถใน ZONTES Smart และ action เปลี่ยนบัญชี

### P2 — Bluetooth ปิดหรือไม่มีสิทธิ์ แต่หน้าค้นหารถบอกให้ออกเดินเข้าใกล้

- เดิน flow: ปิด Bluetooth หรือปฏิเสธสิทธิ์ → เปิดค้นหารถ
- กลไก: `SmartAuto/FindVehicleView.swift:225` แยกเพียง connected กับสถานะอื่นทั้งหมด
- ผลต่อผู้ใช้: คำแนะนำ “อยู่นอกระยะ” แก้สาเหตุจริงไม่ได้
- แก้: แยก poweredOff, unauthorized, scanning, connecting และไม่พบรถ พร้อม action เปิดตั้งค่าตามกรณี

### P2 — หน้าตรวจการเชื่อมต่อปิดปุ่มทดสอบขณะจอรถเชื่อมต่อล้มเหลว

- เดิน flow: auto-connect เริ่มจอรถ → เชื่อมต่อไม่สำเร็จ → บัญชี → ตรวจการเชื่อมต่อ
- กลไก: `SmartAuto/OwnDash/DashScreenService.swift:123` ตั้ง isRunning ก่อน streaming และ setState ที่บรรทัด 321 ไม่เปลี่ยน flag นี้; `SmartAuto/ConnectionDiagnosticsView.swift:167` แสดงสถานะเฉพาะ streaming ส่วนกรณีอื่นแสดงผล diagnostic ที่ยังไม่ได้ทดสอบพร้อมปิดปุ่มเมื่อ isRunning
- แก้: แสดง state/message ของจอรถจริง และมี action หยุดแล้วทดสอบใหม่ หรือไปยังปุ่มควบคุมจอรถโดยตรง

### P2 — โหลดเส้นทางผิดพลาดแล้วไม่มีปุ่มลองซ้ำในหน้าเดิม

- เดิน flow: เลือกจุดหมายตอนเน็ตหลุด → preview แสดง error และปุ่ม “ไป” ใช้ไม่ได้ → เปิดเน็ตกลับ
- หลักฐาน: `SmartAuto/OwnDash/DashDestinationView.swift:346`, `:468`, `:475`
- ผลต่อผู้ใช้: ต้องย้อนกลับเข้าใหม่หรือเปลี่ยนค่าตัวเลือกเพื่อกระตุ้นการโหลด
- แก้: ปุ่มลองอีกครั้งใน error state เรียก loadRoutes และป้องกันการกดซ้อนขณะโหลด

### P2 — การค้นหาที่ผิดพลาดแสดงเหมือนค้นไม่พบ

- เดิน flow: ค้นสถานที่หรือเลือกปั๊มใกล้ตัวตอนอินเทอร์เน็ตใช้ไม่ได้
- กลไก: `SmartAuto/OwnDash/DashDestinationView.swift:42` และ `:219` เปลี่ยนผลลัพธ์เป็นรายการว่างเมื่อเกิด error
- แก้: แยก loading / empty / failed และมี action ลองอีกครั้ง

### P2 — ลบทริปจากหน้ารายละเอียดทันที ไม่มีการยืนยันหรือกู้คืน

- เดิน flow: ทริป → รายละเอียด → ลบทริป
- หลักฐาน: `SmartAuto/Ride/TripsView.swift:191` ลบทันทีแล้ว dismiss ต่างจากหน้าจัดการข้อมูลที่ยืนยันก่อน
- แก้: confirmationDialog ระบุว่าลบประวัติและพิกัดของทริปนี้ ให้ยกเลิกได้

### P2 — บันทึกจุดจอดด้วยมือไม่มีผลตอบกลับเมื่อทำไม่ได้

- เดิน flow: ปฏิเสธสิทธิ์ตำแหน่ง → ค้นหารถ → บันทึกตำแหน่งนี้เป็นจุดจอด
- หลักฐาน: `SmartAuto/FindVehicleView.swift:256`, `SmartAuto/ParkingSpotTracker.swift:154`
- ผลต่อผู้ใช้: โค้ดบันทึกปัญหาลง log แต่ปุ่มไม่ได้แสดง saving/saved/failed ผู้ใช้อาจคิดว่าบันทึกแล้ว
- แก้: แจ้งผลในหน้า พร้อม action เปิดตั้งค่าเมื่อสิทธิ์ไม่พอ

### P2 — กด Go บนคีย์บอร์ดก่อนยอมรับเงื่อนไขแล้วเงียบ

- เดิน flow: กรอกอีเมลและรหัสผ่าน → กด Go โดยยังไม่ติ๊กยอมรับ
- หลักฐาน: `SmartAuto/LoginView.swift:69`, `:173` guard คืนค่าทันทีโดยไม่มี feedback
- แก้: ปิดคีย์บอร์ดแล้วแสดง/ประกาศข้อกำหนดที่ยังไม่ติ๊ก โดยยังห้ามส่ง login จนยอมรับ
- ยังต้องทดสอบ: checkbox อยู่ใต้คีย์บอร์ดบนจอเล็กมากน้อยเพียงใด

## ความเสี่ยงและความสะดวกเพิ่มเติม

- **Cache กับ auto-connect:** `SmartAuto/DataManagementView.swift:210` ตรวจว่าแคชไม่ถูกใช้งานก่อนเริ่ม Task แต่มี await ระหว่าง clearCache กับลบไฟล์ หาก auto-connect เริ่มในช่วงนี้จะไม่มีการตรวจซ้ำ ควรประสานการทำ maintenance กับ lifecycle ของจอรถ นี่เป็น race ที่เป็นไปได้จากโค้ด ยังไม่ได้ reproduce ด้วย runtime
- **ทดสอบหาจอรถดูเหมือนค้าง:** `ConnectionDiagnosticsView.swift:124` มีข้อความคงที่แต่ไม่มี spinner/action ยกเลิก งบ timeout จาก `Shared/DashLocator.swift:70` และ `:225` รวมประมาณ 56 วินาทีในกรณีไม่มี acknowledgement ตัวเลขนี้คำนวณจากโค้ด ไม่ใช่เวลาที่วัดได้ ควรมี progress และยกเลิกในหน้า
- **ลืมรหัสผ่าน:** Login ไม่มีคำแนะนำจัดการรหัสผ่านใน ZONTES Smart ควรเพิ่ม help สั้น ๆ โดยใช้ปลายทางที่ตรวจสอบแล้ว

## ลำดับงานแก้

1. การล็อกกลับหลังส่งเสียงและผลของสวิตช์บันทึกทริป
2. Recovery ของ session, Bluetooth และหน้าตรวจการเชื่อมต่อ
3. Retry ของการค้นหา/เส้นทาง และการยืนยันลบทริป
4. ตรวจ layout, keyboard และ VoiceOver บน simulator/เครื่องจริง แล้วแก้จากภาพและผลที่วัดได้
